## 阅读流程指导

按以下顺序读取和分析论文：

1. **第一遍（快速扫描）**：读取目录和开头部分，获取标题、摘要或执行摘要、引言与问题定义
2. **第二遍（方法理解）**：定位方法、架构或核心论证章节，理解技术细节与数据流
3. **第三遍（证据验证）**：读取实验、表格、案例、量化估算与反方观点
4. **第四遍（补充）**：读取结论、相关工作和局限性，完善理解
5. **完成分析**：写完实验或证据、局限性和个人点评后，再追加工程化三问

对于超过 15 页的 PDF 或较长 DOCX，先扫描目录，再按页码或语义章节分批覆盖全文。至少完整覆盖问题定义、核心方法或论证、证据、局限性和结论；若确实跳过附录或非技术章节，在报告中说明范围。

DOCX 优先保留标题层级、表格、脚注和图片顺序。纯文本提取无法呈现的图表必须单独查看。

## 文件命名与保存

完成分析内容后，使用正文中的正式标题生成一个统一的文件名标题段：

1. 保留中文、英文字母的原始大小写和数字。
2. 将连续的空白和标点替换为单个短横线 `-`。
3. 去除首尾的短横线、点和空白。
4. 若无法可靠提取标题、规范化结果为空或操作系统拒绝该文件名，停止且不修改文件，不使用原文件名猜测标题。

在修改文件前同时检查两个目标路径：

- 原文：`<原目录>/<标题段>.<原扩展名>`
- 报告：`<原目录>/summary-<标题段>.md`

保留原文扩展名。原文已经是目标名称时无需重命名；除此之外，只要任一目标已存在，就停止且不覆盖、不加序号，并在对话中报告冲突路径。

仅在完整分析内容生成并通过上述检查后执行文件操作：重命名原文，将完整报告写入 Markdown 文件。成功后在对话中只返回重命名后的原文路径、报告路径和简短完成说明。此规则仅适用于 `/read-paper`，不改变 `/compare-papers` 的输出行为。
